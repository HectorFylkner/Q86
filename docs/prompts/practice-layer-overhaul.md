# Q86 practice layer — close the loop the Learn overhaul opened

<context>
Q86 (this repo) is a local-first, single-user Next.js + SQLite training platform for GMAT Focus Edition Quantitative Reasoning; the name is the target scaled score. Read README.md and content/lessons/AUTHORING.md first.

A previous session rebuilt the Learn section to course grade, and its decisions are locked: the seven-section chapter template with tiered worked examples (Warm-up → Q86 level, pace targets aligned to `TIME_BENCH` in `lib/pacing.ts`), inline concept checks, wrong-turn notes, a four-note strategy playbook under `content/strategy/`, a prerequisite map in `lib/lessons.ts`, and the loud gate `pnpm verify:lessons`. Do not rework the chapters; touch them only to fix factual drift you discover while cross-referencing. The teaching layer now runs far ahead of the practice layer it feeds — this session's job is the practice layer.

The practice layer's current state, verified against the repo:

- The bank (`scripts/seed-bank.json`) holds 360 questions — README still says 180, which is stale. 298 are problem_solving; 62 are data_sufficiency, a format the GMAT Focus Quant section does not contain (DS lives in Data Insights), and the rebuilt chapters are PS-only by design.
- Difficulty coverage: d1 = 0 items platform-wide, even though `Difficulty` spans 1–5 and `TIME_BENCH` defines a d1 benchmark; d2 = 36, d3 = 108, d4 = 144, d5 = 72. Per-subtopic counts run from 28 (`algebraic_translation`) down to 8 (`interest_profit_discount`, which has only d4/d5).
- Chapter tests (`lib/chapter-tests.ts`) draw 8 questions per subtopic in the blend d2×2, d3×3, d4×2, d5×1 (bar 6/8, pass permanent). Several subtopics cannot fill the blend (`interest_profit_discount` has no d2 or d3; `ratios_proportions` no d3; `percent_change_chains` no d2; `rates_speed_work` no d5; `mixtures_weighted_avg` has only 2 of the 3 required d3) — the selector silently pads with whatever exists, and small pools mean retakes recycle the same questions.
- Every bank item carries a strong contract: five choices, `solution_md` with **Formal path** / **Trigger cue** / **Takeaway** headers, `fastest_path_md`, a per-wrong-choice `trap_map`, and a `numeric_check`; `scripts/verify-bank.ts` enforces structure and recomputes the key via mathjs. New items enter only through the authoring gate `scripts/author/harness.mjs`, where each item's `check()` recomputes the answer from the stem's raw data by brute force. README documents why: an audit found the LLM-cross-solve path (`pnpm seed --api`) had passed 22 defective questions out of 43. That path stays closed.
- The spaced deck (`lib/deck.ts`, `lib/srs.ts`) builds cards only from *missed questions* (front: the item's Trigger cue, back: its Takeaway). The chapters' 160 concept checks, ~190 trigger cues, and 130+ named traps — the artifacts the Learn overhaul created precisely so they could be cemented — are not wired into spaced repetition at all. A student who reads a chapter and misses nothing gets nothing to retain it with.
- The taxonomy defines six error types (`content_gap`, `setup_error`, `calculation_error`, `misread`, `time_pressure`, `guess`) and the playbook note *Reading your misses* prescribes a concrete cure for each — in prose only. Nothing in the product routes a tagged miss to its cure: no link from an error-typed attempt to the specific chapter idea, cue list, or playbook note that fixes it, and the daily plan weights by subtopic accuracy alone.
</context>

<mission>
Make the practice layer worthy of the teaching layer: deep enough that every chapter has real drilling and testing behind it, integrated enough that what a chapter teaches gets cemented and what a miss reveals gets prescribed. Four fronts, in whatever order serves the work:

**1. Bank depth and shape — through the gate, at the chapters' standard.** Author enough new questions that every one of the 24 subtopics supports its chapter-test blend at least twice over with no repeats — a floor of d2 ≥ 4, d3 ≥ 6, d4 ≥ 4, d5 ≥ 2 per subtopic — and go beyond the floor where a subtopic is starved (the 8-item and 10-item subtopics need the most). Every new item goes through `scripts/author/harness.mjs` with a real brute-force `check()`, then `scripts/verify-bank.ts` — never any LLM-verified path. Hold new items to the standard the chapters set: stems at honest GMAT Focus difficulty for their tier, a `trap_map` whose entries name the same wrong turns the chapter's trap gallery teaches, and `Trigger cue` phrasing consistent with the chapter's cue list, so bank and chapter speak one language. Resolve the d1 question with one decision carried everywhere: either author d1 warm-up items per subtopic or formally retire d1 from `Difficulty`, `TIME_BENCH`, and every config that references it — no half state.

**2. Focus-scope alignment.** The 62 data_sufficiency items contradict the platform's Focus-Quant scope and the chapters' PS-only framing. Decide their fate and implement it completely — the default expectation is retiring them from drills, tests, and analytics via the seed pipeline's retirement mechanism (existing attempt history must survive; see constraints), with removal from the bank file as the clean end state. If you instead keep them, they must be fenced behind an explicit, clearly-labeled surface that no default flow reaches. Fix README's stale question count and any other drifted facts you find.

**3. Chapter tests that can do their job.** With the bank deepened, make the test layer honest: selection should prefer questions the student hasn't seen in a previous take of that test where the pool allows, and the silent-padding path should become a loud one — add a coverage gate (`pnpm verify:coverage` or fold it into verify-bank) that fails when any subtopic cannot fill the blend, or cannot fill it twice without repeats, so bank regressions surface at authoring time instead of mid-test. Keep the pass-permanent semantic and the 6/8 bar.

**4. Cement and prescribe — the two missing loops.** First, learn-to-cement: surface the chapters' own artifacts as first-class spaced-repetition material — a per-chapter card pack (trigger cues, concept checks, named traps) that a student can push into the existing deck after reading, scheduled by the same `lib/srs.ts` engine, deduplicated against miss-derived cards, and visible from the chapter page so reading ends with "cement this." Parse the artifacts from the chapters at build/read time via `lib/lesson-parse.ts` rather than duplicating content. Second, miss-to-prescription: when an attempt carries an error type, route it to its cure — content_gap to the specific chapter (deep-linked, prerequisite-aware via `LESSON_PREREQS`), setup_error to the chapter's cue list and the translation chapter, time_pressure to the pacing playbook note plus the attempt's own pacing read, calculation_error to the chapter's speed moves, misread and guess to their playbook prescriptions — and let the daily plan see error-type mix per skill group, not just accuracy, when it weights work. The playbook note *Reading your misses* is the spec; the product should do what it says.

Done means: every subtopic passes the new coverage gate; verify-bank is green over the whole bank including all new items; the deck serves chapter packs and miss cards side by side; an error-typed miss shows its prescription; README and configs match reality; verify:lessons stays green; and `pnpm lint` and `pnpm build` pass.
</mission>

<constraints>
- The authoring gate is the only door. Every new question carries a `check()` that recomputes its answer from the stem's raw data by brute force; an item the harness cannot mechanically verify does not ship, no matter how obviously correct it looks. Trap-map entries and takeaways are prose and can't be brute-forced — recompute their numeric claims yourself the way the Learn session did.
- GMAT Focus Quant scope: problem_solving format, arithmetic and algebra, no geometry, calculator-free arithmetic. Difficulty labels honest to the real exam; a d5 that a strong student solves in 40 seconds is mislabeled.
- The 24 subtopic ids and the rest of `lib/taxonomy.ts` stay fixed, except for a deliberate, fully-carried d1 retirement if you choose it. `ERROR_TYPES` semantics are load-bearing for existing history — extend behavior around them, don't redefine them.
- The user's SQLite database is their training history and is irreplaceable. Schema changes must be additive and applied via the drizzle workflow (`pnpm db:push`); retiring questions must use the seed pipeline's existing retire path so attempt history keeps resolving; never write a migration or script that drops or rewrites user rows. When in doubt about a destructive step, don't take it — leave a note instead.
- Local-first stands: no external services, no new runtime dependencies unless clearly earned, everything works offline with no API key.
- The Learn schema, parser contract, and chapter content are locked. Consume them (via `lib/lesson-parse.ts`); don't fork or duplicate their content into the database — chapters remain the single source of truth for chapter-derived cards.
- UI additions follow the paper-and-ink design language (surface/graphite/ballpoint/redpen/amber tokens, display + mono type) and the platform's existing component idioms. The deck and chapter pages already have visual conventions; extend them, don't invent a second style.
</constraints>
